## Writing Flow

### Step 1: Read the Section Plan
Read `memory/section_plan.md` for the list of subsections with target words, key papers, and writing instructions.

### Step 2a: Load Global Materials (once)
Load these once — they apply to all subsections and must not be re-read per subsection:
1. `memory/section_plan.md` — full subsection list and key_papers
2. `phase0/paper_taxonomy.md` — classification framework for cross-method comparisons
3. `phase0/evolution_narrative.md` — critical narrative arc

### Step 2b: Write Each Subsection Individually
For each subsection in dependency order:
1. Read the paper profiles referenced by this subsection's `key_papers` from `phase0/paper_profiles/<arxiv_id>.md`.
2. Write content following the plan's `writing_instructions`. Use the pre-loaded taxonomy and evolution narrative directly — do not re-read them.
3. Write to `memory/subsections/[id].md` (e.g., `memory/subsections/s2.1.md`).
4. Append a one-paragraph summary (under 15 lines) to `memory/section_summaries.md`.

### Step 3: Assemble Full Draft
After all subsections are written:
1. Read all subsection files from `memory/subsections/`.
2. **Outline compliance check**: verify every section/subsection from `memory/outline.md` has a corresponding file in `memory/subsections/`. Create placeholder subsections for any missing entries.
3. **Redundancy reduction scan**: scan the concatenated text for repeated claims/phrases appearing 3+ times with near-identical wording, and verbatim duplicated paragraphs. Keep the strongest occurrence; replace duplicates with a cross-reference ("as discussed in Section X").
4. Concatenate subsections in order, weaving narrative threads across sections: introduce each thread in the first section it touches, develop it in middle sections, and resolve or re-state it in the culminating section. Add transitional sentences between subsections that reference these threads.
5. Ensure section numbering is consistent.
6. Write the complete draft to `05_draft.md` (overwrite).
7. Append action log (under 20 lines) to `memory/agent_generator.md`.

## Depth Requirements

### `depth_level: "deep"` subsections (Sections 2-5 core methods)
- **Comparison table**: for 3+ methods, include a table (approach, key innovation, supported tasks, limitations)
- **Mechanism analysis**: explain HOW each method works (architecture, algorithm, workflow), not just WHAT it does
- **Pros/cons**: each major method entry must include explicit advantages AND disadvantages
- **Quantitative results**: cite specific benchmark scores or empirical findings where available
- **Target length**: 500-800 words

### `depth_level: "standard"` subsections
- Clear summary with proper citations, trends, and key findings
- Target length: 200-400 words

### Analytical Writing Rules (all levels)
- Every paragraph makes an analytical point — not just a paper summary
- Use comparative transitions: "In contrast to X, Y approaches this by..."
- Group related methods and compare within groups before moving to the next group
- Identify trends, trade-offs, and open questions

## PDF Deep-Read (On-Demand)

When a paper profile lacks the mechanism-level detail you need:
1. Check `pdfs/<arxiv_id>.pdf`. If missing, use `arxiv_download` to get it.
2. Read relevant sections (Method, Architecture, Experiments).
3. Append a note to `memory/agent_generator.md` with key insights.
4. Limit: 2-3 papers per round — paper profiles are the primary source.

## Citation Rules

1. Every factual claim MUST include at least one citation using `[arXiv:XXXX.XXXXX]` format.
2. For specific data points, use `[arXiv:XXXX.XXXXX, §X.X]`.
3. If no relevant citation exists in the pool, note the gap rather than fabricating one.

## Academic Tone

1. **Use measured, comparative language.** Avoid dramatic labels ("epidemic"), absolute closures ("no system does X"), and over-confident superiority ("the correct approach").
2. **Scope-anchor universal claims.** Every use of "all/no/every/never" must specify the boundary (e.g., "among the N methods surveyed here"). If claiming a gap, list the specific methods examined.
3. **Distinguish author analysis from reported facts.** Use "We observe that..." / "This suggests..." for synthesis; prefix cited claims with the source paper's stance ("AutoSurvey reports...").
4. **Constructive gap framing.** "X receives limited attention" over "X is ignored"; "further investigation is needed on Y" over "Y is completely missing".

## Iteration Rules

### Round 1
Write all subsections following the section plan. No focus sections or supervisor feedback to incorporate.

### Rounds 2+
1. Read `memory/supervisor_notes_round[N].md` first (where N is the current round from `memory/iteration_state.md`). Parse the structured YAML:
   - If `actions` is empty or `verdict` is `"no_changes_needed"`, skip modification and proceed to assembly (step 7).
   - Otherwise, iterate over each `action` item: note its `section`, `priority`, `diagnosis`, and `instruction`. Apply all CRITICAL actions first, then MODERATE, then NICE_TO_HAVE.
2. Read `memory/focus_sections.md` if it exists (lists 2-3 sections needing depth improvement).
3. Apply modifications from `memory/supervisor_notes_round[N].md` actions and/or `memory/judge_suggestions.md`. When reading `judge_suggestions.md`, first parse the YAML score header at the top: note the `below_threshold_scores` list and `generator_priority` instruction. Prioritize fixing below-threshold dimensions over nice-to-have suggestions.
4. **Critical Assessment Verification** (if focus sections include Section 5 or a critical assessment):
   For each claim in the critical analysis, verify against paper profiles or PDFs. Mark each as Verified / Qualified / Unsupported / Counter-evidenced. Append a verification log to `memory/agent_generator.md`.
5. **Iteration Evidence Mining** (all Rounds 2+):
   Read previous-round artifacts (judge report, supervisor notes, generator log, section summaries). Extract cross-paper patterns: recurring issues, comparison gaps, evidence contradictions, metric fragmentation. If Section 5 is in focus, integrate these patterns as a new paragraph titled "Structural Problems Revealed by the Iterative Refinement Process".
6. **Focused rewriting**: only rewrite subsections listed in `focus_sections.md` or targeted by action items in `supervisor_notes_round[N].md`. Preserve all others from existing `memory/subsections/` files.
7. Reassemble `05_draft.md` from all subsection files.
