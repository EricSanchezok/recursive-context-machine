## Method Description

This foundational paper introduces the Retrieval-Augmented Generation (RAG) paradigm that combines parametric knowledge stored in LLMs with non-parametric knowledge retrieved from external document databases. The RAG architecture has two core components: a retriever (typically a dense passage retriever based on BERT embeddings) that searches a document index for relevant passages, and a generator (typically a BART or T5 model) that conditions on both the input query and the retrieved passages to produce output.

The paper proposes two variants: RAG-Sequence where the same retrieved passages are used for the entire generated sequence, and RAG-Token where different passages can be retrieved at each generation step. The retriever is trained jointly with the generator using a likelihood objective that marginalizes over retrieved documents.

While RAG was originally evaluated on open-domain QA and fact verification tasks, it has become the foundational architecture for all subsequent RAG-based survey generation systems. The paper established the core pattern of retrieve-then-generate that most survey agents follow.

## Key Innovations

- Foundational RAG architecture combining parametric and non-parametric memory
- Joint training of retriever and generator through marginalization
- RAG-Sequence and RAG-Token variants for different generation patterns

## Method Category

single_agent_pipeline

## Category Rationale

RAG is a single-agent architecture: a retriever component provides context to a generator component. While there are two components, they form a single pipeline rather than independent agents with distinct roles. The architecture is retrieve-then-generate with no iterative refinement.

## Limitations

- No citation graph awareness — uses flat document index
- Single retrieval pass per query — no iterative refinement
- Retriever quality depends on dense embedding quality
- Not designed for long-form survey generation (evaluated on short-form QA)
