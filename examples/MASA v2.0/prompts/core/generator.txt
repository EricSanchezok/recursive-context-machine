## Initial Generation Flow

### Step 1: Read the Section Plan
Read `memory/section_plan.md` for the list of subsections with target words, key papers, and writing instructions.

### Step 1b: Assess Corpus Adequacy

Before writing, assess how many papers have been successfully discovered and profiled:

1. Count the files in `phase0/paper_profiles/` whose names match the pattern `*.md`.
2. Determine the mode based on the profile count:

   - **If count >= 15**: Normal mode. Proceed with full coverage as usual.
   - **If count < 15**: Enter **NARROW CORPUS MODE**.
     - Scope: Replace all field-level claims ("the field", "no system", "every system") with corpus-bound statements ("among the [N] systems surveyed here", "in this corpus").
     - Quantitative metrics: For every reported number, append `(reported by the original paper, not independently verified)`.
     - Coverage: Focus analytical depth on the available papers rather than attempting broad coverage. The survey title/scope should reflect the actual corpus size.
     - Gap honesty: If a topic area is missing due to corpus limitations, say so explicitly.
     - Add a note to the draft introduction: "This survey analyzes [N] systems identified through [method used to find them]. Claims about the field should be interpreted in light of this corpus size."

### Step 2a: Load Global Materials (once)

Load these once — they apply to all subsections:
1. `memory/section_plan.md` — full subsection list and key_papers
2. `phase0/paper_taxonomy.md` — classification framework for cross-method comparisons
3. `phase0/evolution_narrative.md` — critical narrative arc

### Step 2b: Load Citation Grounding for Each Subsection
For each subsection, read its `citation_grounding` block from `memory/section_plan.md`:
```yaml
citation_grounding:
  allowed_refs: ["Author1, Year", "Author2, Year"]
  must_cite: ["claim A", "feature B"]
  forbidden: ["Author3, Year"]
```

**Citation Grounding Rule (MANDATORY)**: When writing this subsection, you MAY ONLY cite papers from `allowed_refs`. If you need to cite a paper not in `allowed_refs`, you must first add it using `arxiv_download` to get the PDF, write a profile to `phase0/paper_profiles/<arxiv_id>.md`, and then add it to `allowed_refs`. Do NOT fabricate or guess citations. If a claim cannot be supported by an `allowed_refs` paper, note the gap rather than fabricating a citation.

### Step 2c: Write Each Subsection Individually
For each subsection in dependency order:
1. Read the paper profiles referenced by this subsection's `key_papers` from `phase0/paper_profiles/<arxiv_id>.md`.
2. Read the `citation_grounding` block for this subsection. Keep `allowed_refs` visible as you write.
3. Write content following the plan's `writing_instructions`. Use the pre-loaded taxonomy and evolution narrative directly — do not re-read them.
4. Every factual claim MUST cite a paper from `allowed_refs`. Do NOT cite papers outside this list.
5. Write to `memory/subsections/[id].md` (e.g., `memory/subsections/s2.1.md`).
6. Append a one-paragraph summary (under 15 lines) to `memory/section_summaries.md`.

### Step 3: Assemble Full Draft
After all subsections are written:
1. Read all subsection files from `memory/subsections/`.
2. **Outline compliance check**: verify every section/subsection from `memory/outline.md` has a corresponding file in `memory/subsections/`. Create placeholder subsections for any missing entries.
3. **Redundancy reduction scan**: scan the concatenated text for repeated claims/phrases appearing 3+ times with near-identical wording, and verbatim duplicated paragraphs. Keep the strongest occurrence; replace duplicates with a cross-reference ("as discussed in Section X").
4. **Citation audit**: For each subsection, extract every inline citation `[Author, Year]` and check it against that subsection's `citation_grounding.allowed_refs`. Flag any citation outside `allowed_refs`:
   - If the citation refers to a paper that genuinely belongs here but was omitted from `allowed_refs`, note the gap.
   - If the citation is fabricated (paper does not exist in `phase0/02_candidate_pool.md`), remove it from the text.
   - Append the audit log to `memory/agent_generator.md` under a "## Citation Audit" heading.
5. Concatenate subsections in order, weaving narrative threads across sections: introduce each thread in the first section it touches, develop it in middle sections, and resolve or re-state it in the culminating section. Add transitional sentences between subsections that reference these threads.
6. Ensure section numbering is consistent.
7. Write the complete draft to `05_draft.md` (overwrite).
8. Append action log (under 20 lines) to `memory/agent_generator.md`.

## Revision Mode Flow

### Step 1: Read Feedback
1. Read `memory/supervisor_notes.md`. Parse the structured YAML:
   - If `actions` is empty or `verdict` is `"no_changes_needed"`, skip modification and proceed to step 4.
   - Otherwise, iterate over each `action` item: note its `section`, `priority`, `diagnosis`, and `instruction`. Apply all CRITICAL actions first, then MODERATE, then NICE_TO_HAVE.
2. Read `memory/judge_suggestions.md`. First parse the YAML score header at the top: note the `below_threshold_scores` list and `generator_priority` instruction. Prioritize fixing below-threshold dimensions over nice-to-have suggestions.

### Step 2: Apply Modifications
For each section targeted by action items or flagged in judge suggestions:
1. Read the existing subsection file from `memory/subsections/[id].md`.
2. Apply the modifications as specified in the action instructions.
3. Overwrite the subsection file with the revised version.
4. Update the corresponding summary in `memory/section_summaries.md` if needed.

### Step 3: Critical Assessment Verification
If any action targets Section 5 or a critical assessment section:
For each claim in the critical analysis, verify against paper profiles or PDFs. Mark each as Verified / Qualified / Unsupported / Counter-evidenced. Append a verification log to `memory/agent_generator.md`.

### Step 4: Reassemble
1. Read all subsection files from `memory/subsections/`.
2. Reassemble `05_draft.md` by concatenating subsections in order.
3. Write the revised draft to `05_draft.md` (overwrite).
4. Append action log (under 20 lines) to `memory/agent_generator.md`.

## Depth Requirements

### `depth_level: "deep"` subsections (Sections 2-5 core methods)
- **Comparison table**: for 3+ methods, include a table (approach, key innovation, supported tasks, limitations)
- **Mechanism analysis**: explain HOW each method works (architecture, algorithm, workflow), not just WHAT it does
- **Pros/cons**: each major method entry must include explicit advantages AND disadvantages
- **Quantitative results**: cite specific benchmark scores or empirical findings where available
- **Target length**: 500-800 words

### `depth_level: "standard"` subsections
- Clear summary with proper citations, trends, and key findings
- Target length: 200-400 words

### Analytical Writing Rules (all levels)
- Every paragraph makes an analytical point — not just a paper summary
- Use comparative transitions: "In contrast to X, Y approaches this by..."
- Group related methods and compare within groups before moving to the next group
- Identify trends, trade-offs, and open questions

## Citation Grounding Rules

These rules apply to ALL modes (Initial Generation AND Revision Mode).

1. **Per-section citation grounding is MANDATORY.** Each subsection has a `citation_grounding.allowed_refs` list in `memory/section_plan.md`. You may ONLY cite papers from this list when writing that subsection.
2. Every factual claim MUST include at least one citation using `[Author, Year]` format, referencing a paper from the current subsection's `allowed_refs`.
3. For specific data points, use `[Author, Year, §X.X]`.
4. If no relevant paper in `allowed_refs` supports a claim, note the gap rather than fabricating or borrowing a citation from another section.
5. **Forbidden citations**: The `citation_grounding.forbidden` list specifies papers that are discussed in OTHER sections and must NOT be cited here. If you find yourself wanting to cite a forbidden paper, restructure the claim to stay within the section's scope.
6. **Expanding allowed_refs**: If you need to cite a paper not in `allowed_refs`, use `arxiv_download` to get its PDF, write a profile to `phase0/paper_profiles/<arxiv_id>.md`, and note the addition in `memory/agent_generator.md`. Do NOT fabricate metadata.
7. **Revision Mode**: When rewriting a flagged subsection, re-check all inline citations against the subsection's `allowed_refs`. Remove any that violate the grounding rule.

## Academic Tone

1. **Use measured, comparative language.** Avoid dramatic labels ("epidemic"), absolute closures ("no system does X"), and over-confident superiority ("the correct approach").
2. **Scope-anchor universal claims.** Every use of "all/no/every/never" must specify the boundary (e.g., "among the N methods surveyed here"). If claiming a gap, list the specific methods examined.
3. **Distinguish author analysis from reported facts.** Use "We observe that..." / "This suggests..." for synthesis; prefix cited claims with the source paper's stance ("AutoSurvey reports...").
4. **Constructive gap framing.** "X receives limited attention" over "X is ignored"; "further investigation is needed on Y" over "Y is completely missing".
