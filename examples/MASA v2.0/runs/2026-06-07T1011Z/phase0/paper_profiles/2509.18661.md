## Method Description

Agentic AutoSurvey introduces a multi-agent architecture with four specialized agent types for collaborative survey generation. The system employs an Orchestrator Agent that decomposes the survey topic into subtopics and dispatches work to three specialist agents: a Search Agent responsible for retrieving relevant papers, a Writing Agent that drafts section content based on retrieved materials, and a Review Agent that evaluates draft quality, identifies gaps, and triggers refinement.

The workflow proceeds iteratively: the Orchestrator first generates a high-level survey plan. The Search Agent retrieves papers for each planned section using keyword queries and embedding similarity. The Writing Agent then drafts content for each section, citing retrieved papers. The Review Agent evaluates the draft across 12 quality dimensions (including coverage, coherence, citation quality, and readability) and provides structured feedback. If quality thresholds are not met, the loop iterates — the Search Agent re-queries for specific gaps, the Writing Agent revises, and the Review Agent re-evaluates.

A notable feature is the system's ability to process 75–443 papers per topic, depending on the breadth of the subject. The four-agent design enables division of labor and continuous quality control through the review-refine cycle. The system was evaluated by having LLMs (the agents themselves) generate surveys about LLMs, creating a self-referential evaluation scenario.

- 12-dimensional quality evaluation rubric embedded in the review agent's feedback loop
- Iterative refinement triggered by structured multi-dimensional quality scores
- Demonstrated at scale processing 75–443 papers per survey topic

## Category Rationale

The paper employs four distinct agent roles (Orchestrator, Search, Writing, Review) with specialized prompts and responsibilities. The iterative review-refine loop between Review and Writing agents creates a quality control mechanism characteristic of multi-agent architectures. Each agent type uses the same underlying LLM but with different system prompts and access patterns.

## Limitations

- No citation graph awareness — relies entirely on search API-based retrieval
- Self-referential evaluation (LLMs surveying LLMs) may not generalize to other scientific domains
- All agents use the same underlying LLM — no actual specialization beyond prompt engineering
- Retrieval is not citation-aware, limiting paper discovery to search engine rankings
- No forward/backward citation chaining to discover relevant papers beyond initial search
