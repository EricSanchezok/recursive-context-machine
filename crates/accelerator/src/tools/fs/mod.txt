File system operations — read, write, edit, list, and stat files or directories. Use the `action` parameter to select the operation.

### Read

Reads a file from the local filesystem. You can access any file directly by using this tool.

Usage:
- The filePath parameter should be absolute whenever possible; relative paths are resolved against the current working directory.
- By default, reads up to {DEFAULT_READ_LIMIT} lines starting from the beginning. For large files, use `offset` and `limit` to read specific sections.
- Lines longer than {MAX_LINE_LENGTH} characters are truncated with "...".
- Results include file metadata (type, size, modification time) followed by line-numbered content in `00001| content` format.
- Use `offset` (0-based) to skip lines, and `limit` to control how many lines are returned.
- Output is capped at {OUTPUT_CAP_KB} KB; use offset+limit to narrow the range when reading very large files.

### Write

Writes a file to the local filesystem.

Usage:
- This tool will overwrite the existing file if one already exists at the provided path.
- ALWAYS prefer `edit` (action="edit") for targeted in-place changes. Only use write when replacing the entire file or creating a new one.
- This tool will error if the target path is a directory.
- Parent directories are created automatically if they do not exist.

### Edit

Performs exact string replacements in files.

Usage:
- Provide the exact text to find as `oldString` and its replacement as `newString`.
- The edit will FAIL if `oldString` is not found in the file content. The error will suggest the most similar lines.
- The edit will FAIL if `oldString` appears multiple times. Either provide more surrounding context in `oldString` to make the match unique, or use `replaceAll: true` to change every occurrence.
- Use `replaceAll` for batch renames (e.g., renaming a variable throughout a file).
- When copying text from a `read` result, preserve the exact indentation as it appears after the line number prefix. Never include the line number prefix in `oldString` or `newString`.
- ALWAYS prefer editing existing files. NEVER create new files with edit — use write for that.
- The tool matches `oldString` using cascading strategies: exact match, line-trimmed, anchor-based, whitespace-normalized, indentation-flexible, escape-normalized, boundary-trimmed, and context-aware. This means minor formatting differences (trailing whitespace, indentation shifts, escaped characters) are handled automatically.

### List

Lists a directory as a recursive tree.

Usage:
- Hidden files and directories (such as `.git`, `.github`, `.vscode`) are hidden by default. Set `showHidden: true` only when you explicitly need them.
- `limit` caps the total number of rendered entries across the whole tree.
- `maxDepth` controls how deep to traverse. Default: 4.
- `perDirectoryLimit` prevents one large directory from consuming the entire output. When a directory has more entries, the output shows an omitted-count line for that directory.
- Output uses 📁 for directories and 📄 for files, indented by depth.
- For codebase exploration, use list for a quick structural overview and `find` for targeted file/text/AST search.
