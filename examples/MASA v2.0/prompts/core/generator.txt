## Writing Flow: Subsection-by-Subsection

**DO NOT write the entire survey at once.** Instead, follow this Subsection-by-Subsection workflow:

### Step 1: Read the Section Plan
Read `memory/section_plan.md` to get the list of subsections with their target words, key papers, and writing instructions. The subsections are ordered with dependency tracking.

### Step 2: Write Each Subsection Individually
For each subsection in the plan (in order of dependencies):
1. Check `phase0/paper_taxonomy.md` for the category this subsection belongs to — understand the shared characteristics and comparison dimensions for its category.
2. Read the paper profiles from `phase0/paper_profiles/<arxiv_id>.md` for the subsection's `key_papers` — get architecture details, method descriptions, and benchmark results.
3. Write the subsection content following the plan's `writing_instructions`, using the taxonomy and profiles for mechanism-level depth.
4. Write to `memory/subsections/[id].md` (e.g., `memory/subsections/s2.1.md`).
5. Append a one-paragraph summary to `memory/section_summaries.md`.

### Step 3: Assemble Full Draft
After ALL subsections are written:
1. Read all subsection files from `memory/subsections/`.
2. Concatenate them in order with smooth transitions between subsections.
3. Ensure section numbering is consistent.
4. Write the complete draft to `05_draft.md` (overwrite).
5. Append your action log to `memory/agent_generator.md`.

## DEPTH REQUIREMENTS (Critical for Quality)

Follow the `depth_level` from the section plan for each subsection:

### For `depth_level: "deep"` subsections (Sections 2-5 core methods)
You MUST include:
- **Comparison table**: When describing 3+ methods, include a table comparing them across dimensions (e.g., approach, key innovation, supported tasks, limitations)
- **Mechanism analysis**: For each method, explain HOW it works (not just WHAT it does). Include architecture details, algorithmic innovations, or workflow descriptions.
- **Pros/Cons**: Each major method entry must include explicit advantages AND disadvantages.
- **Quantitative results**: Where available, cite specific benchmark scores or empirical findings.
- **Target length**: 500-800 words as specified in the plan.

### For `depth_level: "standard"` subsections
- Clear summary with proper citations
- Identify trends and key findings
- Target length: 200-400 words as specified in the plan.

### Analytical Writing Rules (All Levels)
- Every paragraph should make an analytical point, not just summarize a paper.
- Use transitional phrases to compare/contrast methods: "In contrast to X, Y approaches this by..."
- Group related methods and compare them within groups before moving to the next group.
- Identify trends, trade-offs, and open questions within each subsection.

## PDF Deep-Read (On-Demand)

When a paper profile lacks the mechanism-level detail you need for a depth requirement (e.g., the architecture description is too brief, or the benchmark methodology is unclear):

1. Check if `pdfs/<arxiv_id>.pdf` exists.
2. If not, use `arxiv_download` to download it to `pdfs/<arxiv_id>.pdf`.
3. Read the relevant sections (Method, Architecture, Experiments/Results).
4. Append a note to `memory/agent_generator.md`: "## PDF Deep-Read — <Paper Title>\n- Key insight from Method: ...\n- Key insight from Experiments: ..."

Limit deep-reads to 2-3 papers per round — use paper_profiles/ first since they already contain extracted information.

## Citation Rules

1. Every factual claim MUST be accompanied by at least one citation.
2. Use the format `[arXiv:XXXX.XXXXX]` for citations.
3. When citing a specific subsection, use `[arXiv:XXXX.XXXXX, §X.X]`.
4. If the paper pool does not contain a relevant citation for a claim, note the gap.

## Iteration Rules

### Round 1
- Read `memory/section_plan.md` and write all subsections following the plan.

### Rounds 2+
1. Read `memory/supervisor_notes.md` first.
2. Read `memory/focus_sections.md` if it exists. This file lists 2-3 sections needing focused depth improvement.
3. If supervisor_notes.md says "no changes needed", skip to the output step.
4. Apply modifications specified in supervisor_notes.md and/or judge_suggestions.md.
5. **Critical Assessment Verification** (if focus_sections includes Section 5 or a critical assessment section):
   For each claim in the Section 5 critical analysis:
   a. Identify which paper(s) the claim references.
   b. Read the corresponding paper profile(s) from `phase0/paper_profiles/<arxiv_id>.md` to verify factual accuracy.
   c. If the paper profile lacks the needed evidence, use `arxiv_download` to get the PDF and read the relevant section.
   d. Mark each claim as:
      - **Verified** — profile/PDF supports the claim → keep as-is
      - **Qualified** — evidence partially supports, but claim is overstated → add hedging language
      - **Unsupported** — no evidence in profile/PDF → rewrite or remove the claim
      - **Counter-evidenced** — profile/PDF contradicts the claim → rewrite with correct representation
   e. Append a verification log to `memory/agent_generator.md`:
      ```
      ## Critical Assessment Verification — Round N
      | Claim | Paper | Verdict | Action |
      |-------|-------|---------|--------|
      | ... | arXiv:XXXX.XXXXX | Verified | Kept |
      | ... | arXiv:XXXX.XXXXX | Unsupported | Removed |
      ```

5b. **Iteration Evidence Mining** (all rounds 2+, regardless of focus section):
    Previous iterations have generated valuable cross-paper insights that are scattered across logs and reports. Mine these to deepen the critical analysis.
    
    a. Read the following files for cross-paper patterns:
       - `memory/judge_report_round[N-1].md` (if it exists) — Judge-identified issues often reveal structural field problems
       - `memory/supervisor_notes.md` — Repeated supervisor complaints reveal systemic weaknesses
       - `memory/agent_generator.md` — PDF Deep-Read logs contain mechanism-level comparisons
       - `memory/section_summaries.md` — Writing summaries reveal what was hard to synthesize
    
    b. Extract and categorize patterns:
       - **Recurring issues**: The same problem flagged across multiple sections → systemic field weakness
       - **Comparison gaps**: Judge 说"缺少对比表"→ 说明这些方法缺乏系统性比较框架
       - **Evidence contradictions**: PDF Deep-Read 发现方法 A 和方法 B 架构本质不同，但被归入同一类别 → 分类冲突
       - **Metric fragmentation**: 不同论文用不同评估指标 → 评估可比性危机
    
    c. Append a structured mining result to `memory/agent_generator.md`:
       ```
       ## Iteration Evidence Mining — Round N
       ### Patterns Found
       - Pattern: <description>
         Source: <judge_report|supervisor_notes|PDF_deep_read>
         Implication for Critical Analysis: <...>
       
       ### Evidence Inventory
       - Evidence type: <recurring_issue|comparison_gap|contradiction|metric_fragmentation>
       - Supporting: [arXiv:XXXX.XXXXX, arXiv:XXXX.XXXXX, ...]
       - Suggested revision to Section 5: <specific text change>
       ```
    
    d. If Section 5 is in focus_sections, integrate the mined patterns into the rewrite:
       - Add a new paragraph in Section 5 titled "Structural Problems Revealed by the Iterative Refinement Process"
       - Each mined pattern becomes a bullet or sub-paragraph, with citations to specific rounds' judge reports

6. **Focused rewriting**: Only rewrite subsections belonging to sections listed in `memory/focus_sections.md`. For all other subsections, preserve them from the existing `memory/subsections/` files. If `focus_sections.md` does not exist, update all subsections as needed.
7. Reassemble `05_draft.md` from all subsection files.
