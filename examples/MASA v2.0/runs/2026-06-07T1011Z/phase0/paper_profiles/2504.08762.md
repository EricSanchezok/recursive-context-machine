## Method Description

InteractiveSurvey introduces a human-in-the-loop architecture where the user participates actively in the survey generation process. Unlike fully automated systems, InteractiveSurvey provides a user interface for specifying preferences, reviewing intermediate outputs, and making decisions that guide the generation. The system supports three key interactive features: reference categorization (users can classify retrieved papers into categories like "foundational," "methodological," "related but not central"); outline refinement (users can edit the generated outline before drafting begins); and iterative feedback (users can review drafts and request revisions on specific sections).

The architecture proceeds through: (1) Initial Retrieval — papers are gathered via search and citation graph traversal based on the user's topic query; (2) Interactive Reference Categorization — the user categorizes retrieved papers, which informs the relative emphasis each paper receives in the survey; (3) Interactive Outline Refinement — the system proposes an outline and the user can restructure, merge, or delete sections; (4) Drafting — sections are generated based on the user-approved outline and paper categories; (5) Interactive Revision — the user reviews the draft and requests changes, which the system implements.

This interactive loop makes the survey generation process transparent and controllable, addressing the "black box" concern of fully automated systems. The trade-off is higher user effort compared to push-button automation.

- agent_count: 1 (single LLM backend with user in the loop)

- citation_graph_detail: "Uses citation graph traversal for initial paper discovery. Users can also manually add seed papers for additional traversal."
- iteration_strategy: "interactive (user decides when to iterate, revise, or finalize)"

## Key Innovations

- Three-stage user interaction (reference categorization, outline refinement, draft review)
- Transparent generation process with user control at each stage
- Reference categorization informing paper emphasis in the generated survey

## Category Rationale

InteractiveSurvey's defining characteristic is the user-in-the-loop architecture. The system cannot generate a survey without user input at multiple stages (reference categorization, outline approval, draft review). This hybrid human-AI interaction pattern clearly distinguishes it from fully automated pipelines.

## Limitations

- Higher user effort compared to push-button systems — requires domain expertise to categorize references and refine outlines
- Single LLM backend limits perspective diversity in generated content
- User interaction increases total generation time
- Citation graph traversal is basic BFS — no advanced graph analytics
