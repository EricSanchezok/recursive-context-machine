## Method Description

AutoSurvey2 extends the original AutoSurvey pipeline with parallel section generation, iterative refinement, and real-time retrieval capabilities. The system introduces a multi-stage architecture where section drafting occurs in parallel across multiple LLM instances, significantly improving throughput. After initial generation, an iterative refinement loop allows each section to be revised based on feedback from coherence checks and coverage analysis.

A key architectural improvement is the introduction of real-time retrieval: unlike the original AutoSurvey's single-pass offline retrieval, AutoSurvey2 can re-query paper databases during the refinement phase to fill identified gaps. This "retrieve-then-refine" loop enables the system to discover papers that become relevant as the survey's focus crystallizes during writing. The system also supports user-provided seed papers as starting points for retrieval expansion.

AutoSurvey2 maintains the staged decomposition approach of its predecessor but adds a planning phase where the system explicitly identifies which topics and subtopics need coverage before retrieval. This is followed by parallel drafting of sections, each handled by an independent LLM call with its own retrieved context, and a final integration phase that stitches sections together with cross-references and consistent formatting.

## Category Rationale

AutoSurvey2 uses multiple parallel LLM instances for section drafting, coordinated by a central integration module. This qualifies as a multi-agent pipeline, though agents are homogeneous (same LLM, different context assignments) rather than specialized. The refinement loop adds iteration, and the system supports user input for seed papers.

## Limitations

- No explicit citation graph traversal — relies on search APIs rather than forward/backward chaining
- Homogeneous agents (all same LLM) — no specialization for different aspects of survey writing
- Citation quality remains unaddressed — no verification that generated citations are accurate
- Real-time retrieval may introduce latency and cost overhead
