Find code in your project — by file name pattern, by regex in file contents, or by AST structure. Use `mode` to pick the method.

All modes respect `.gitignore` rules in traversed directories. Hidden files and directories are included (not skipped).

### files — Find files by glob pattern

Returns matching file paths sorted by modification time (newest first).

Usage:
- `pattern` must be a glob, e.g. `**/*.rs`, `src/**/*.ts`, `*.md`.
- `path` narrows the search to a subdirectory. Omit to search the whole project.
- Capped at 200 results. If you get too many, narrow with `path`.
- Fire multiple find calls in parallel when you have several patterns to try — it's faster than running them one at a time.

### text — Find text in file contents with regex

Returns file paths, line numbers, and matching lines. Results are grouped by file and sorted by modification time (newest first).

Usage:
- `pattern` must be a regex, e.g. `fn\s+\w+`, `TODO`, `pub struct`.
- `include` filters files by glob, e.g. `*.rs` or `*.{ts,tsx}`. Only those files are searched.
- `path` narrows the search to a subdirectory. Omit to search the whole project.
- Capped at 200 results. Lines longer than 2000 characters are truncated.
- To count occurrences in matched files, use the shell tool to run `rg` directly.

### ast — Find code with AST-aware structural patterns

Unlike regex, this mode understands code syntax. It matches across whitespace/formatting differences and only matches valid code constructs.

Meta-variables:
- `$VAR` — Matches a single AST node (identifier, expression, statement).
- `$$$` — Matches zero or more AST nodes (function arguments, array elements, etc.).

Usage:
- `pattern` must be a complete, valid AST node. Incomplete patterns fail.
- `lang` (required) is the language identifier: bash, c, cpp, csharp, css, elixir, go, haskell, html, java, javascript, json, kotlin, lua, nix, php, python, ruby, rust, scala, solidity, swift, typescript, tsx, yaml.
- `context` adds surrounding lines around each match. Omit to get just the matching line.
- Use when regex would be fragile (e.g., finding function definitions without matching comments that contain the same words).
- Common mistakes:
  - Python: no trailing colons. Use `def foo($$$)` not `def foo($$$):`.
  - Functions/classes: include params and body. Use `function $N($$$) { $$$ }` not `function $N`.
  - Incomplete patterns: `const $X` will fail — use `const $X = $Y`.
- Requires `sg` (or `ast-grep`) CLI installed. On macOS: `brew install ast-grep`.
